MCP Server exposes a native Streamable HTTP JSON-RPC 2.0 endpoint directly inside Odoo at /mcp — no external middleware or bridge process required. AI assistants such as LibreChat, Claude, ChatGPT, Microsoft Copilot, Cursor, and VS Code connect directly to your Odoo URL and execute every query and write under the authenticated Odoo user's real ACLs and record rules, with complete audit logging.

What is Model Context Protocol (MCP)?

Model Context Protocol (MCP) is an open standard that gives AI assistants a uniform, secure way to discover schemas, query records, and run business workflows across enterprise systems. One Odoo integration serves every MCP-compatible AI client with zero vendor lock-in.

MPI GmbH Security Hardening

Production-safe defaults built directly into the module

Chatter Email Guard (Default: Internal Notes Only)

post_message blocks public comments (subtype="comment") and explicit partner_ids notifications by default so AI agents cannot accidentally email customers. Admins can opt in via Allow External Chatter Comments.

Rate Limiting Enabled by Default

Per-user request rate limiting (mcp_server.enable_rate_limiting) is active out of the box (300 requests/minute per worker) across /mcp, REST, and XML-RPC routes.

OAuth 2.1 Opt-In & DCR Kill-Switch

OAuth 2.1 is disabled by default so API-key-only deployments expose zero /mcp/oauth/* surface (HTTP 404). When OAuth is enabled, Dynamic Client Registration (/mcp/oauth/register) can still be disabled independently for pre-registered clients.

Attachment Download Link Control

Keeps the strict 1-hour default link TTL and adds Allow Unauthenticated Download Links so administrators can disable signed /web/content links completely when only inline attachment reads should be allowed.

Key Features & Capabilities

Native /mcp Endpoint

Streamable HTTP JSON-RPC 2.0 right inside Odoo. Supports smart field selection, aggregations, batch creates/updates, and attachment tools.

Custom Tools (Server Actions)

Expose curated business verbs (e.g. confirm_sale_order or post_internal_note) backed by Odoo server actions with custom JSON schemas and security groups.

Granular Model Gates

Explicit per-model toggles for Read, Create, Update, Delete, and Method Calls, enforced on top of Odoo's native ACLs and record rules.

OAuth 2.1 & Read-Only Consent

Optional PKCE S256 OAuth login lets users authorize AI sessions with their own Odoo account and optionally grant read-only (mcp:read) scope.

MCP-Only API Keys

Mint dedicated API keys scoped strictly to /mcp so leaked credentials have a minimal blast radius and cannot call generic RPC endpoints.

Audit Trail & User Context

Every tool call, denial, rate-limit hit, and login attempt is logged with metadata only. User timezone and allowed companies are passed on handshake.

Technical Specifications

Requirements & Odoo.sh

  • Odoo 18.0
  • Python packages in repository root requirements.txt: authlib>=1.6.12,<1.7.0, defusedxml, packaging
  • Any MCP-compatible AI assistant

Supported Protocols

  • Native MCP at /mcp (Streamable HTTP, JSON-RPC 2.0)
  • MCP protocol revisions 2025-11-25 & 2025-06-18
  • OAuth 2.1 (RFC 9728 / 8414 / 7591, PKCE S256) — opt-in
  • REST & XML-RPC proxy routes

Security Controls

  • Rate limiting enabled by default (300 req/min/worker)
  • OAuth 2.1 off by default + independent DCR switch
  • post_message restricted to internal notes by default
  • Optional kill-switch for unauthenticated attachment links
  • MCP-only API keys, per-model allowlists & audit logging
